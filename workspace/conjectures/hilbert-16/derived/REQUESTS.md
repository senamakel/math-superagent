Posted with `request_research` and rewritten whenever one is posted or a note is written. Do not edit this file; the next write re-derives it.

A request closes when a note carries a claim block with `answers: <id>`. That is deliberate: whoever fills a gap has to write down what was established, so "was the gap filled" is read off the library rather than asserted by whoever went looking. An open request with a precise **falsifies** column is the best query this run can hand a search — better than anything available from the problem statement alone.

**Working with this ledger.** Sections here are bounded and rows are shortened, so what is above is not all of it. `read_ledger` returns entries in full:

```
read_ledger { ledger: "requests" }
read_ledger { ledger: "requests", id: "<one of the ids above>" }
read_ledger { ledger: "requests", status: "<a status above>" }
read_ledger { ledger: "requests", query: "<text to search for>" }
```

`list_ledgers` says what fields and statuses this one has, and what else the workspace keeps. To change it: `request_research`, which states what is missing and what would settle it. Editing this file changes nothing — it is re-derived on the next write and your edit goes without a warning.
