# Pattern report — minimal-excess structure in the six open classes

**Pattern finder** · all numbers below were produced by exact-integer programs in
this run; every claim carries its evidence class and its falsification term.

## The sequences studied

For each of the six open classes `r ∈ {1, 121, 169, 289, 361, 529}` mod 840,
`n = 840k + r`. Since all six satisfy `n ≡ 1 (mod 4)`, write `n = 4m + 1`;
then any solution `4/n = 1/x + 1/y + 1/z` has `x ≥ m + 1 = (n + 3)/4`. The
program (`code/minimal_x/minimal_x.py`, extended to `k ≤ 450` by
`code/minimal_x/extended_verify.py`) finds, for every such `n`, the **minimal**
`x` attaining a solution, by exact divisor enumeration over `(nx)²` — every
returned triple is re-verified by exact `Fraction` arithmetic.
`code/out/witnesses.json` (12 entries) is reproduced exactly.

- **`x(k)`** = minimal x. Always `x(k) = 210k + (r + 3)/4 + e(k)` for an
  integer **excess** `e(k) ≥ 0` (data: `n = 4m+1` ⇒ `x ≥ m+1`).
- **`e(k)`** = x − (n+3)/4, the true excess; `d(k) = 4x − n = 4e + 3`.
- **`y(k), z(k)`** accompanying the minimal-x solution (kept in
  `code/out/open_class_sequences.json`, `code/out/extended_minimal_x.json`).

**Conclusion from the tools:** the excess is not a polynomial, not periodic,
not a constant-coefficient recurrence, and not catalogued. Its structure is
**multiplicative/number-theoretic**, not additive.

## The structural finding (conjecture, exact over every computed row)

**Theorem-shaped claim (verified, not yet proven for all n).** Let
`n = 4m + 1` and `x_e = (n + 4e + 3)/4` (so `d := 4x_e − n = 4e + 3`). Then
`4/n = 1/x_e + 1/y + 1/z` has a positive-integer solution iff

> `−n·x_e (mod 4e + 3)` is the residue of some divisor of `(n·x_e)²`.

*Why it is correct:* the two-term equation `d/(nx) = 1/y + 1/z` is equivalent
to `(dy − nx)(dz − nx) = (nx)²` with both factors ≡ −nx (mod d); the map
`solution ↔ divisor u = dy − nx of (nx)², u ≡ −nx (mod d)` is a bijection,
and min(u, (nx)²/u) ≤ nx ensures y, z > 0 ([written out in
`code/minimal_x/divisor_criterion_validate.py`]).

**Verification:** 2705/2705 rows (all six classes, k ≤ 450), *both* directions:
criterion true at the minimal excess on every row, criterion false for every
`e′ < e` on every row, and brute-force split agrees with the criterion on every
candidate `e′` tested. A weaker subgroup-membership version failed on 56 rows
exactly because the target residue lies in the subgroup generated by the prime
factors but is not attained by any divisor (exponent cap); the divisor-residue
version fixes all 56 ([exception analysis in
`code/minimal_x/exceptions_analyze.py`]).

**First falsification term:** any `n = 4m+1` (in one of the six classes, or
indeed any `n ≡ 1 mod 4`) where the criterion and the brute-force two-term
search disagree. None exists among the 2705 rows computed (k ≤ 450). The check
is cheap to run on any single n: factor `(nx)²`, enumerate divisor residues mod
`4e+3` (exponents capped at `2·v_q(nx)`), compare to `−nx`.

## Exact simple corollaries (also verified 2705/2705)

- `e = 0` (i.e. `x = (n+3)/4`, `d = 3`) is possible
  **iff some prime `q ≡ 2 (mod 3)` divides `n` or `(n+3)/4`**
  — because then `q | nx` makes the needed `2 (mod 3)` residue available.
- `e ≤ 1` (i.e. `d = 7` works) is possible
  **iff some prime `q` divides `n` or `(n+7)/4` with `q mod 7 ∈ {3,5,6}`**
  (quadratic non-residues mod 7).
- The minimal `e` always lies in the subgroup of `(Z/4e+3)^*` generated by the
  prime factors of `n·x_e`; the 56 exceptions all satisfy this but not the
  divisor-residue condition.

## What this means for the covering-identity question

The excess `e(k)` is **not** eventually constant; it is governed by the
multiplicative (divisor-residue) structure of `n` and `n + 4e + 3` — so any
identity family `x = ((n + 4E + 3)/4)` covers exactly the n whose excess lies
in `{E} ∪ above`, which is a set of density governed by the prime-factor
conditions above, and no fixed finite excess covers a full residue class mod
840 (each class contains n with arbitrarily... at least with the observed large
excesses e=14). **Consequence:** low-excess identities (the known type-I/II
shapes, which correspond to x ≈ n/4 with bounded excess) can never cover a full
open class — the residual classes exactly contain n whose relevant prime factors
reside in the wrong residue classes. This explains *why* the standard families
fail on the six squares: any shape of bounded excess fails on infinitely many
members of each open class.

## What would falsify the pattern

1. The exact criterion failing on a row it has not been tested on (k > 450, any
   of the six classes, or any n ≡ 1 mod 4 outside them) — a 10-second check.
2. A growth/sparsity contradiction: if some future bound showed the minimal
   excess must exceed the divisor-residue criterion's reach (e.g. if e were
   forced to grow with k), the covering interpretation would break; nothing in
   the 2705 rows suggests e grows with k (max e = 14 at n ≈ 119000).
