# Approach: the linear code of the triangle geometry (Assmus–Key), NOT the adjacency matrix

```approach
idea: The linear code over F_2 and F_3 of the point-block incidence matrix N of
  the triangle geometry — a partial Steiner triple system on 99 points, 231
  blocks (triangles), 7 per point — with its 2-rank, 3-rank, hull, and Smith
  normal form as the invariants. Named theory: Assmus–Key "Designs and their
  Codes", the classical p-rank of Steiner triple systems.
mechanism: The 231 triangles are lines; N is the 99 x 231 incidence matrix.
  Two exact identities bind it to the graph: NN^T = 7I + A (rows = points,
  each pair of points shares as many lines as common neighbours) and
  N^T N = 3I + C3 (columns = lines, line-line intersection = the triangle
  graph). Over F_3, 7 = 1 so NN^T = I + A, and every column has weight 3 = 0,
  so the column space lies in the even-weight subspace 1^perp of dimension 98
  — a constraint with no analogue for the adjacency matrix. Over F_2,
  NN^T = I + A. The code C = row(N) is generated by 99 vectors of weight 7
  (replication 7); its dimension (the p-rank of the geometry), its hull
  C cap C^perp, and its weight enumerator are invariants of the LINE SET, not
  of the spectrum of A: two partial STS with the same collinearity graph
  parameters can in principle carry different incidence codes. This is NOT the
  refuted `macwilliams-binary-code-arc`, which took the row span of A+I (a
  99x99 two-weight code whose enumerator Delsarte fixes by the parameters
  alone). N is a different, non-square (99x231) matrix, and its code theory is
  Assmus–Key / STS-p-rank (the 2-rank of STS(v) genuinely varies with the
  system), not the Delsarte two-weight theory. The honest risk is that for a
  partial STS forced to have NN^T = 7I+A the p-rank could still turn out to be
  parameter-determined; the first step is precisely the check that decides this.
status: grounded
speculative: medium — concrete and computable, but must first be shown not to be
  a parameter-determined invariant like the two refuted code/SNF routes.
precedent:
  - Assmus, "On 2-ranks of Steiner triple systems" (Electron. J. Combin. 1995),
    https://doi.org/10.37236/1203 : the p-rank of an STS(v) genuinely varies;
    for STS of deficient 2-rank the "carrier" code depends on order AND 2-rank,
    so the incidence p-rank is NOT determined by v alone.
  - Bonisoli, "On the binary codes of Steiner triple systems", Designs, Codes,
    Crypt. 8 (1996) 29-43, https://link.springer.com/article/10.1007/BF00130567 :
    the binary code spanned by the point-by-block incidence matrix of an STS is
    the object; the classical (projective/affine) STS are characterized by their
    codes — the incidence code carries real structure.
  - Shi, Xu, Krotov (2019), "The number of the non-full-rank Steiner triple
    systems", J. Combin. Des., https://doi.org/10.1002/jcd.21663 : formulas for
    the NUMBER of STS(v) of a given 2-rank r2<v and 3-rank r3<v-1; no STS has
    both r2<v and r3<v-1 — confirming both 2- and 3-rank are discriminating.
  - Haemers, Peeters, van Rijckevorsel (1998), "Binary Codes of Strongly Regular
    Graphs", https://research.tilburguniversity.edu/en/publications/dca56971-63a6-4942-b8f7-5a3ddc69ae31 :
    p-ranks of incidence/adjacency of designs and SRGs are "often, but not
    always, determined by the parameters" — the honest open question that the
    run's own first-step (compute rank_2/rank_3 of N on the two controls) decides.
verdict: The MECHANISM is grounded in the literature — the p-rank of a triple
  system's incidence code genuinely distinguishes non-isomorphic systems of the
  same order, so N is not a spectrum-determined invariant like the two refuted
  A-based routes. No source shows the p-rank of an NN^T = 7I+A partial STS is
  parameter-determined, so nothing here refutes the approach. But the literature
  also does NOT compute the decisive values: whether rank_2(N) / rank_3(N) / SNF(N)
  separate (9,4,1,2) from (243,22,1,2) [and hence what 99 would force] is a
  computation this run must do, not a citation. Until the two controls give
  DIFFERENT ranks, the approach is not a live 99-obstruction — if they agree, it
  reverts to refuted as parameter-determined exactly like macwilliams/higman.
first-step: (exact, sympy over F_2, F_3, and Z) Build N from the triangle
  enumeration in code/lib (the same enumeration the oracle uses), and compute
  rank_2(N), rank_3(N), the hull dimensions, and SNF(N) for rook(3) (N is
  9x6, the 3x3 grid's rows+columns) and for bvls_graph() (N is 243x891).
  Record the values and test whether they are forced by (v,k,lambda,mu) alone;
  if the two controls give DIFFERENT ranks, the invariant is live and the next
  question is what value NN^T = 7I+A (mod p) with column-weight-3 forces at 99.
```

## Why this is a different object from what was refuted

`macwilliams-binary-code-arc` was closed because the row span of A+I is a
Delsarte two-weight code fixed by the parameters; `higman-module-restriction`
because the SNF/critical group of A and of the Laplacian are determined by the
spectrum (Lorenzini, Ducey et al.). Both are functions of A's *spectrum*. The
incidence matrix N is not: it records which triangles exist, and its p-ranks are
the classical invariants that actually distinguish non-isomorphic Steiner triple
systems of the same order (Assmus–Key; the 2-rank of STS(19), etc.). The exact
relations NN^T = 7I+A and N^T N = 3I+C3 are the bridge that turns the geometry
into a coding question, and they are not used anywhere else in this run.

## Negative-control discipline

The 99-specific arithmetic is different from the two controls only through the
shape of N (99x231 vs 9x6 vs 243x891) and through A mod p. The first step
computes the two controls exactly so that any later 99-conclusion can name the
value it forces and show the controls sit elsewhere. If research finds the
p-rank of a partial STS with prescribed NN^T is fixed by (v,k,lambda,mu), the
approach is refuted and the reason will be recorded here.
