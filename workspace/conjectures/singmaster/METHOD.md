Solve by Diophantine analysis of the curves `C(x,k1) = C(y,k2)` and by effective height bounds. For each fixed pair `(k1,k2)` this is an algebraic curve whose genus grows with the parameters, so Faltings gives finitely many rational points above a threshold and Siegel gives finitely many integral points even at genus 1. Reason about that family: compute the genus as a function of `k1,k2`, find where it crosses 1, and ask what changes as the pair grows — whether the curves acquire structure that makes a bound uniform, and where Baker's method on linear forms in logarithms yields an effective height bound with a computable constant. Use every other capability in service of that argument rather than instead of it.

Three cautions this problem has already earned:

Finiteness is not a bound, and finiteness for each pair separately is already known. Faltings and Siegel are ineffective in the sense that matters here: they give "finitely many" with no count computable in `k1,k2`, while Singmaster needs a constant uniform over all pairs at once. This is the same shape as the blocker recorded in the magic-square workspace — a theorem that applies cleanly and yields no usable number. Say early whether the chosen route produces an effective bound or another ineffective one, and mark every claim with whether its bound is effective and whether it is uniform in `k`.

Fix the counting convention before stating anything. `C(n,k) = C(n,n-k)`, so occurrences pair up, and a bound of 8 counting both is a bound of 4 counting one. Every claim must name the convention it uses.

The deliverable is an upper bound, so the failure mode is an argument that proves a bound too small. `3003 = C(3003,1) = C(78,2) = C(15,5) = C(14,6)` and its four mirrors is the witness set, and every claimed bound or lemma must be run against `code/out/witnesses.json`. A claimed `B < 8`, or any lemma implying one, is false — record it refuted, not weakened. A bound not run against the witnesses is `asserted`, never `checked`. The known infinite family with multiplicity at least 6 is a second constraint of the same kind: verify it and keep it in view.

On compute: never build the triangle. For fixed `a` only `k <= log2(a)` can occur since `C(n,k) >= C(2k,k) >= 2^k`, so invert `C(n,k) = a` by binary search in `n` for each small `k` — cheap, exact, no table. Parallelise across `a` or across `(k1,k2)` pairs, which are independent; `code/lib/parallel.py` and `code/lib/PARALLEL.md` are in this workspace, on a box with 28 CPUs and no container CPU quota. If you reach for `smt_solver` on the Diophantine system, be honest about what it can return: nonlinear integer arithmetic is undecidable in general, an `unknown` is not a proof, and a `sat` or `unsat` is meaningful only with the encoding size and the exact bounds stated beside it. Say in every captured output how many workers ran and what range was covered; a result without its bound is not a result.
