```approach
idea: Binary-digit constraint via Lucas's theorem modulo 2 — for odd a, every representation (n,k) with C(n,k)=a must satisfy k ⊆ n (bitwise submask). Convert this combinatorial constraint to a bound on N(a) without passing through the Diophantine curve or Siegel/Faltings. The engine is digit combinatorics, not algebraic geometry.
status: adopted
mechanism: For odd a, C(n,k) odd ⇒ k ⊆ n bitwise ⇒ n ≥ k and n has 1s wherever k has 1s. Let M = floor(log2 n). Then the submask condition forces n ≥ 2^{popcount(k)} (roughly). For any fixed k, the equation C(n,k) = a determines at most k values of n (polynomial equation of degree k), so for large k the representation count is bounded per k. The challenge is bounding how many DISTINCT k can represent the same odd a. The submask constraint restricts (n,k) pairs: if k is large relative to n, then k ⊆ n forces n to have dense binary expansion, which in turn forces C(n,k) to be large for given n,k. The mechanism is: (1) partition potential representations by k-range: k ≤ K0 (small, at most K0·(log a) total candidates) vs. k > K0 (large, where the submask + Sylvester constraints together bound the count); (2) for small k, use SST 1995 + Matveev 2000 to get an effective constant (per-pair, but only finitely many pairs to check); (3) for large k, the binary-submask constraint combined with Sylvester primes forces a contradiction unless N(a) is small.

What makes this different from the refuted kummer-lucas-p-adic: that approach tried to bound multiplicity by the SIZE of a single p-adic class and failed because one class can be exponentially large. This approach does NOT bound class size — it bounds how many class MEMBERS can land on the SAME VALUE a. The distinction: a row of Pascal's triangle with all entries odd (n=2^m-1) has 2^m distinct values, but the question is whether one of those values can appear many times across different rows. The binary-submask constraint is a necessary condition that the (n,k) pairs of a given odd a must satisfy SIMULTANEOUSLY — they must all be submasks of their respective n's AND all produce the same binomial value. This is a system of constraints, not a class-size estimate.

precedent: Lucas's theorem (1878) is classical. The odd-only Pascal triangle is studied (Stein 1980, Stolarsky, Harborth). No known result in the library applies this to Singmaster's conjecture or bounds multiplicities within the odd triangle. The approach is unchecked against the literature — research should check whether the odd-only triangle's value multiplicities have been studied.

first-step: Write a program that, for all odd n up to 2^18 ≈ 262,144, enumerates all k with k ⊆ n (submask enumeration), computes C(n,k) exactly, and records multiplicities. The goal: determine the maximum multiplicity of any odd value in this range. If the maximum is ≤ 8 (matching 3003), this is numerical evidence that the binary constraint is strong enough. If a value appears ≥ 10 times, that's a new witness. Either way, this gives concrete data on the sparsity of odd binomial values — something not yet in the library. The compute cost: each row n has 2^{popcount(n)} odd entries; worst-case n=262143 (popcount≈18) gives ~262K entries; total entries across all rows to 2^18 is ≈3.5·10^7 (Sloane A006046). With Python big integers, each C(n,k) is at most C(262144,131072) ≈ 10^{78900} — enormous but exact via Python's arbitrary precision. However, we only need to compare VALUES, so we can use a hash of the value (or compare factorizations). Better: use that for n ≤ 2^18, all C(n,k) fit in ~80000 decimal digits, which Python can handle but the total memory for 3.5·10^7 big integers is prohibitive. Instead, use a two-pass approach: first compute all C(n,k) values and hash them to 64-bit (collision risk), or use the fact that we're looking for MAXIMUM multiplicity, so we only need to detect when a value repeats. A 128-bit hash (SHA-128 or Python's built-in hash) reduces collision risk to negligible. The cost: 3.5·10^7 big-integer computations, each O(k) multiplications, maybe 5-10 minutes on 28 cores. Launch with timeout 540, parallel across n ranges.
```
