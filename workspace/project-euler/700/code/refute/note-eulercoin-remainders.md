# Refutation: "Eulercoins = Euclidean remainders" is false

**Statement attacked:** the rung R-small-descent merge note in
`research/weakened/eulercoin.md`:

> "the coins are the successive remainders in the Euclidean algorithm on
> (M, A); each coin's index recovered from the quotients."

**Result: refuted (by hand, verified against the run's own oracle).**

## Counterexample (smallest)

Take the run's own tiny oracle (M, A) = (17, 7). Hand-anticipated coins
7@1, 4@3, 1@5, 0@17, sum 12 — confirmed by `code/verify_recurrence.py`.

- Euclidean remainders of (17, 7): 17 = 2·7 + **3**, 7 = 2·3 + **1**, 3 = 3·1 + **0**.
  So the "coins = remainders" claim predicts second coin = **3**.
- True Eulercoins of 7n mod 17: 7@1, **4**@3, 1@5, 0@17. The second Eulercoin
  is **4**, not 3.

Why 3 is not a coin: the value 3 first occurs at n = 15, but by then 4 (n=3)
and 1 (n=5) have appeared, so 3 is never a new strict minimum.

## Checked against the original statement

Verified directly: 7n mod 17 for n=1..17 is 7,14,4,11,1,8,15,5,12,2,9,16,6,13,3,10,0.
Strict prefix minima are exactly 7@1, 4@3, 1@5, 0@17, sum 12.

## Correct structural fact (not refuted)

The true descent is NOT the plain Euclidean remainders but the record-low index
recurrence (smsxgz/brob26), `research/summaries/record-low-recurrence.md`:

    n_{k+2} = ceil( c_{n_k} / c_{n_{k+1}} ) · n_{k+1} - n_k

On (17,7): n_1=1 (c=7), n_2=3 (c=4), n_3=ceil(7/4)·3-1 = 2·3-1 = 5 (c=1),
n_4=ceil(4/1)·5-3 = 4·5-3 = 17 (c=0). Coins 7,4,1,0 at indices 1,3,5,17.
The recurrence reproduces the true coins; the "Euclidean remainder" shortcut
to the second coin value is what fails.

## What the engine said

`find_counterexample` on `code/refute/eulercoin-rmdr.p` returned **undecided**
at every size reached, and even the calibration problem `calibrate.p`
(conjecture `1 = 2`) returned undecided. The finite-model finder is not
decisive on these purely-ground encodings, so the engine here is not
independent confirmation — the refutation rests on the hand-check and the
run's own brute-force oracle, which agree.

## Consequence for the run

R-tiny-scan (sum 12) is correct and unaffected. The rung merge text should
NOT assert "coins = Euclidean remainders"; the coins are generated by the
index recurrence (or, equivalently, best-approximants-of-the-second-kind /
continued-fraction convergents of A/M), which is the theory already sourced in
`research/summaries/record-low-recurrence.md`.
