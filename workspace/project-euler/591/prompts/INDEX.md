# Index — prompts

What each file in this folder is for. Keep it current: describe a file when you create it, and refresh this index after adding, renaming, or deleting files.

| File | Purpose |
| --- | --- |
| `goals.md` | Orchestrator guidance: translate the goal into observable completion criteria; verify-by-running; reject enumeration; require small-case checks. |
| `inventor.md` | Guidance for when the approach has stalled: propose one representation-change, not a menu; cite the named theory; never enumerate. |
| `librarian.md` | Guidance for building the `research/` reference library: descriptive names, current INDEX, prefer primary sources, never store a published contest answer. |
| `orchestrator.md` | Guidance for sequencing work: understand, research, derive, implement, verify; reject answer-space search; spawn independent agents in parallel. |
| `organizer.md` | Guidance for this role (workspace housekeeping): keep every INDEX.md current and accurate, mark superseded files, never edit the work itself. |
| `pattern_finder.md` | Guidance for finding structure in computed data; distinguishes an exact finding from a conjecture; an invented pattern is worse than none. |
| `reflection.md` | Guidance for judging an attempt (not the problem): call out unverified answers and unreported progress; the lesson must be actionable. |
| `research.md` | Guidance for the research role: prefer original papers, return exact URLs, state theorem hypotheses, never fetch a published answer. |
| `scholar.md` | Guidance for distilling a downloaded source into a short `<name>.md` summary; one file per source, index it with `describe_file`. |
| `tool_builder.md` | Guidance for the only role that can run code: exact arithmetic, complexity stated up front, worked examples first, toolkit helpers described in `toolkits/INDEX.md`. |
