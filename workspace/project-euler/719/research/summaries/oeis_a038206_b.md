# A038206 — the S-number roots m, and the intended solver recursion

Source: https://oeis.org/A038206 and its b-file
(`research/sources/oeis_a038206_b.full.md`; full record at `[[oeis_a038206]]`).

This is the complement of A104113: the square **roots** m such that m² is an
S-number. A term m satisfies: the decimal digits of m², read left to right, can
be split and accumulated with plus signs (2+ blocks) to equal m.

**What it establishes.**
- Terms begin 0,1,9,10,36,45,55,82,91,99,100,… (so n=m² gives the A104113
  terms 0,1,81,100,1296,2025,3025,6724,8281,9801,10000,…).
- `a(n) = sqrt(A104113(n))` (Tarantini).
- Every term ≡ 0 or 1 (mod 9).
- **The exact solver (Michael S. Branicky, 2021),** reproduced verbatim:

```python
def expr(t, d):                 # can target t be built from digits d (add +'s)?
    if t < 0: return False
    if t == int(d): return True
    return any(expr(t - int(d[:i]), d[i:]) for i in range(1, len(d)))
def ok(n): return expr(n, str(n*n))
```

  `ok(n)` returns True for exactly the roots. `expr` is the digit-partition
  predicate: try each first-block length, recurse on the reduced target and the
  remaining suffix. This is precisely the intended solver.
- **b-file coverage:** 408 terms end at exactly term 408 = **1000000 =
  isqrt(10¹²)**; term 409 = 1005291 > 10⁶. So the first 408 terms are exactly
  the roots m with m² ≤ 10¹². Summing their squares gives T(10¹²) by a route
  entirely disconnected from the solver's recursion.

**Hypotheses / holds-here:** holds. The recursion is the run's solution.py
method; the b-file provides the independent verification route.
