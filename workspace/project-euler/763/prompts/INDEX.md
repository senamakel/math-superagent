# Index — prompts

What each file in this folder is for. Keep it current: describe a file when you create it, and refresh this index after adding, renaming, or deleting files.

| File | Purpose |
| --- | --- |
| `goals.md` | Goals-role guidance: translate the goal into observable completion criteria, delegate sourced facts to research and calculations to the tool-builder, and require a small-case check before any full-size run. |
| `inventor.md` | Inventor-role guidance, called when an approach stalls: propose a change of representation (generating function, bijection, transform, theorem reformulation), one specific proposal, never enumeration. |
| `librarian.md` | Librarian-role guidance: build research/ as a local reference library, descriptive names, keep research/INDEX.md current, prefer primary sources, never store a published contest answer. |
| `orchestrator.md` | Orchestrator-role guidance: sequence understand → research → derive → implement → verify, reject answer-space searching, spawn independent work in parallel and combine into one derivation. |
| `organizer.md` | The organizer's role instructions (the file behind this task): keep indexes matching disk, describe every file, keep the root and code/ trees navigable, and leave reflections/ alone. |
| `pattern_finder.md` | Pattern-finder-role guidance: work from actually computed sequences in the workspace using the analysis/recurrence tools, report exact recurrence as a conjecture, not proof. |
| `reflection.md` | Reflection-role guidance: judge the attempt (unverified equals unsolved, invented progress is no progress) and name a specific actionable lesson for the next attempt. |
| `research.md` | Research-role guidance: prefer primary sources, return exact URLs and precise theorem statements with hypotheses, never search for a published contest answer, file downloads under research/. |
| `scholar.md` | Scholar-role guidance: read research/INDEX.md first, digest each source into a sub-thousand-token summary with theorem statements, hypotheses, and what follows for this problem. |
| `tool_builder.md` | Role guidance for the tool-builder (the only agent that runs code): state method and complexity before running, reproduce the statement's worked examples first, use exact arithmetic, edit with apply_patch, build a lib/ module for repeated routines, and describe each file. |
