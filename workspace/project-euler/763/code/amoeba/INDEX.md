# Index — code/amoeba

What each file in this folder is for. Keep it current: describe a file when you create it, and refresh this index after adding, renaming, or deleting files.

| File | Purpose |
| --- | --- |
| `amoeba_extend.py` | Extended BFS oracle + structural-feature dumper for PE763. Drives the fixed-width bitmask BFS level by level (importing next_level_bits/decode_bits/feature_record from lib/amoeba), records D(N) each level, stops when frontier exceeds cap, and for levels in [dump_lo,dump_hi] writes each config's level histogram, max level M, and bbox extents to /workspace/data/level_N.txt. Reproduces D(2)=3, D(10)=44499; cap 5,000,000 states. |
| `amoeba_verify.py` | Second, structurally independent 3D BFS oracle for PE763 D(N): builds a non-blocked-cube set and re-derives the successor step, verifying the primary bitmask D(14)=5949063 by a second route. Validated by reproducing D(0..13). Canonical copy relocated from code/ root. |
| `bfs_more.py` | Level-by-level exact BFS oracle for D(N) using COMPACT per-level bitmask (width = level+1) to extend the oracle; stops on time/state cap and writes D(0..Nmax). Carries extant results D(2)=3, D(10)=44499 and D(14)=5949063; exponential state space, it is the oracle not the solver. |
| `brute.py` | Naive 3D BFS oracle for PE763 D(N): prints D(2) and D(10). Now imports the canonical reachable_sets/D(d=3) from lib/amoeba; the former local reachable_sets copy (identical to code/brute.py's) was consolidated into lib/amoeba.D(N,d). Verified: D(2)=3, D(10)=44499 match the statement. |
| `brute_bits.py` | Memory-compact int-bitmask 3D BFS oracle for D(N): each config a fixed-width W bitmask so encoding is level-independent. Imports next_level_bits from lib/amoeba.py (not duplicated). Cross-checked against the frozenset oracle for N=0..12. Canonical copy relocated from code/ root. |
| `brute_capped.py` | Capped naive 3D BFS oracle for PE763 D(N): drives levels up to a max-depth arg, stops when the frontier exceeds 600k states, prints the full D(N) sequence and checks D(2)=3, D(10)=44499. NOTE: still carries a local 3D one-step division_states copy (semantically identical to lib/amoeba.forward_level(level,3), not diverged, but not yet consolidated). |
| `brute_extended.py` | Level-by-level BFS oracle for D(N): one BFS step per level from N=0 up, recording D(N) every level, stops when a level exceeds a time budget. Verified reproducing D(2)=3 and D(10)=44499. Same exponential state space as brute.py; pushes the oracle a little further. Canonical copy relocated from code/ root. |
| `configs_n3_n4.py` | BFS oracle with exact frozenset-of-tuples arithmetic that prints the actual reachable configurations of Project Euler 763 for N=3 (9 states) and N=4 (30 states), sorted, one per line, to code/out/configs_n3_n4.txt. Asserts the counts match D(3)=9, D(4)=30. Now imports its one-step successor as next_level_fs from lib/amoeba.py (previously a local copy). |
| `d2_bfs.py` | Clean exact level-by-level BFS oracle for the 2D amoeba D2(N) using the compact bitmask encoding from lib/amoeba2d; pushes much higher than the d=3 ceiling of N=14 because the 2D state space grows far more slowly. Writes D2(0..Nmax) to code/out/d2_values.txt. Validated at small N against the frozenset oracle (d2_check.py). |
| `d2_check.py` | Frozenset oracle for the 2D amoeba; independent validation that the bitmask BFS matches for N=0..12 (D2 = 1,1,2,4,9,20,46,105,243,561,1301,3014,6995). |
| `distinct_hist_count.py` | Counts DISTINCT level-histogram tuples a_k=#cubes at level k=x+y+z present among all reachable configs at each level N, by driving the same lib/amoeba.next_level_bits BFS (keeps only the frontier + small histogram set, not the config set, to fit the 2 GiB cap). Answers whether the distinct-histogram counts continue 1,1,2,3,5,8,13,22,36,60,100 for N=2..12 into N=13,14 (the OEIS A186085 question); writes code/out/distinct_hist_counts.txt and self-checks frontier sizes equal D(13)=1749267 and D(14)=5949063. |
| `dump_hists.py` | Sidecar dumper for the 3D amoeba: drives the same fixed-width bitmask BFS as lib.amoeba.next_level_bits and, for each level N=0..10, prints every distinct level-histogram tuple a_k = #cubes at level k=x+y+z. Studies the structure behind the finding that distinct-histogram counts match OEIS A186085 (1D smooth/sandpile compositions). The histogram tuple equals the whitespace-separated token list before the first pipe on each data/level_N.txt line. |
| `mhist_13_14.py` | Level-by-level exact BFS for PE763 (lib/amoeba.next_level_bits, fixed-width bitmask) that also counts distinct configs at N=13 and N=14 grouped by max level M = max(x+y+z), saving the M-histograms to code/out/mhist_13_14.txt. Totals verified: N=13 sum 1749267 = D(13), N=14 sum 5949063 = D(14), both independently established. Does not write full config dumps. Runs ~69s total; needs explicit gc.collect() between levels to stay under the 2 GiB cgroup cap (first attempt OOM'd, fixed by the GC call). |
| `verify_distinct_hist_from_data.py` | Definition-check that counts DISTINCT level-histogram tuples in the existing data/level_N.txt dumps (N=2..12): a level histogram is the tuple a_k = #cubes at level k=x+y+z, equal to the whitespace-separated token list before the first ' |
| `voidance_analysis.py` | Voidance-set/collapse structural probe for the 3D amoeba: for each reachable config S at N=0..6 (computed by lib.amoeba.next_level_fs BFS), iterates the deterministic reverse collapse c(S) — remove the 3 top-level cells (asserted exactly 3, forming the full child-triangle of an empty parent via lib.amoeba.triangle_parent) and replace with that parent — until it reaches {(0,0,0)}, recording the total voided-cell count (rem) and number of collapse steps per config, then tabulates how configs distribute by void-set size and by step count per N. Carried a forbidden sys.path.insert(0,'/workspace/code') which was removed (imports already resolve by package name since /workspace/code is on PYTHONPATH). |
| `voidance_set_size.py` | Voidance-set-size structural probe for PE763: for each reachable config S at N=0..6 (lib.amoeba.next_level_fs BFS), iterates the deterministic collapse (remove the 3 top-level cells — asserted exactly 3 and the full child-triangle of an empty parent via lib.amoeba.triangle_parent — and add that parent; all visited cells accumulate) until it reaches {origin}, then records the total voided-cell count (all_occ minus origin) per config and tabulates how configs distribute by voidance-set size per N. Uses lib.amoeba.next_level_fs and triangle_parent. NOTE: still carries a forbidden sys.path.insert(0,'/workspace/code') at the top; imports already resolve by package name since /workspace/code is on PYTHONPATH (like its sibling voidance_analysis.py, which had the same insert removed) — the insert is harmless but redundant and has not been stripped from this file. |
