# Seal: L1.0 — the OEIS lookup batch

This batch answers one question that governs the whole run: **is the 3D amoeba
sequence D(N)=1,1,3,9,30,99,336,1134,3855,13086,44499,151263,514419,1749267,5949063
(a machine-computed, BFS-verified sequence to N=14) a known catalogued sequence
with a closed form — and if not, what does the catalogue hand over anyway?**

Read this note instead of the ten below it. Everything here is one of three
kinds of result: a **ruled-out closed form** (the D(N)=...,motzkin/fib family
candidates — all dead by term comparison), an **authoritative negative** (the
two direct OEIS searches), or a **made identity** (A007902 = the 2D amoeba;
A055999/A074171/A134227 = the run's own Q_2 level column). The single most
valuable row is [[oeis_a007902]]: it is the catalogued relative that actually
matches this process, taken in dimension two.

## The four ruled-out closed-form families

Each of these was filed hoping a catalogued closed form would turn D(N) into an
evaluation. All four fail by **term-wise comparison against the BFS-verified
D(N)** — the cheapest, most decisive test, and one that needs no further
hypotheses than that the BFS terms are right (verified to N=14 by three
independent implementations). D(N) diverges from every one of them at n=2 or
before, so **none applies and none should be revisited unless new data change
the first terms.**

- **[[oeis_a001006]]** — Motzkin numbers A001006: g.f. (1-x-sqrt(1-2x-3x^2))/(2x^2),
  recurrence (n+2)a(n)=(2n+1)a(n-1)+(3n-3)a(n-2), a(n)=Σ_k C(n,2k)Cat(k).
  a(2)=2 vs D(2)=3 → diverge at n=2. Claim `dN-not-motzkin`, proved.
- **[[oeis_a005207]]** — A005207 = (F(2n-1)+F(n+1))/2 (Fibonacci), linear
  recurrence 4a(n-1)-3a(n-2)-2a(n-3)+a(n-4), base ~2.6. a(2)=2 vs D(2)=3.
  Claim `dN-not-fibonacci-f2n1`, proved. Its exponential base is quantitatively
  unlike D(N)'s observed ~×3.4 frontier factor — a different growth regime, not
  just a shifted one.
- **[[oeis_a086246]]** — Motzkin variant, g.f. (1+x-sqrt(1-2x-3x^2))/2
  (a(n+2)=A001006(n)). 0,1,1,1,2,4,9,... agrees nowhere useful (D(0)=1 vs
  a(0)=0, D(2)=3 vs a(2)=1). Claim `dN-not-a086246`, proved.
- **[[oeis_a168049]]** — Motzkin variant, g.f. (3-x-sqrt(1-2x-3x^2))/2,
  "essentially A086246". 1,0,1,1,2,4,9,... matches only D(0)=1. Claim
  `dN-not-a168049`, proved. Because it inherits the Motzkin exclusion, nothing
  new beyond ruling it out.

Net: **no fixed-shape/closed-form catalogued family governs 3D D(N)**. The
growth rate alone (~×3.4/division) already rules out every base-2.3–2.6
constant-recurrence candidate here.

## The two made identities — what the catalogue actually does give us

**[[oeis_a007902]] — A007902, "number of pebbling configurations with n pebbles",
is the catalogue's match to this process in dimension two.** Terms
1,1,2,4,9,20,46,105,243,561,1301,... (indexed by pebbles). The 2D amoeba
D_2D(N) equals A007902(N+1) on every published/BFS term (established in
research/amoeba2d_pebbling_a007902.md; claim `d2d-equals-a007902`). This is not
3D D(N), but it is the **governing two-dimensional relative**, and the note
carries the exact recurrence that reproduces it:

- Asymptotic (Knessl, 2006, via Kotesovec): a(n) ~ c·d^n with
  d = 2.321642199494…, c = 0.122687073421….
- **Exact two-index recurrence** (memoized G(k,m), Alois P. Heinz):
  ```
  G(k,0)   = 2G(k-1,0) + G(k,1)   + [k==2]
  G(k,1)   = G(k-3,0) + 2G(k-2,1) + G(k-1,2) + G(k-4,1)
  G(k,m)   = G(k-m-2,m-1) + 2G(k-m-1,m) + G(k-m,m+1)
  a(n)     = G(n,0)  (a(1)=1)
  ```
  This is exactly the CGMO G(k,m) recurrence (CGMO eqs 2.1–2.3) that the
  library's L0/L2 pebbling notes verify, and it is the **template this run is
  trying to lift to 3D** (thread [[lift_gkm_to_3d]]). Its key features: it is a
  *double* (k,m) index — it does not reduce to a one-index closed form, which is
  the current blocker for the 3D lift. Cross-referenced from A007901.

**[[oeis_a055999]] / [[oeis_a074171]] / [[oeis_a134227]] — three looks at the same
quadratic, and one of them is a real hit for this run.** All three are
"essentially the same": a(n)=n(n+7)/2 (A055999; A074171 is 1,3 then that
quadratic; A134227 is (n-1)(n+6)/2 + [n=1]). These were *not* filed as D(N)
candidates — they match the run's own structural column. The hit: the PE763
**max-level column** Q_2(N)=R(N,N-2)/3^(N-5) equals, for N=6..14, the values
4,9,15,22,30,39,49,60,72 = A055999(N-5), i.e. **Q_2(N)=(N-5)(N+2)/2**. This
confirms, from an independent catalogued sequence, a previously-conjectured
closed form for the level of the second-max level. Exact over N=6..14 (BFS
data); **conjecture past that** — the coincidence is not a proof at full size
and the parameter (N-5) needs structural justification. Q_3, Q_4, Q_5 column
lookups were misses (no catalogued match), so *only the Q_2 column* has a
catalogue-confirmed form.

## What this batch lets the run compute, bound, or rule out

- **Ruled out**: every Motzkin/Fibonacci-family closed form for D(N) (four
  claims, all proved by term comparison); any hope that OEIS indexes 3D D(N)
  (two negatives).
- **Computed/confirmed**: D_2D via the exact G(k,m) recurrence (a reusable
  check for the 3D DP), and the Q_2(N) level column closed form on N=6..14.
- **Bound**: A007902 grows as ~0.1227·2.3216^n — a hard data point that the
  3D D(N) (~×3.4/division) outgrows the 2D relative, so no 2D-asymptotic
  rescaling directly bounds D(N); the 3D structure is genuinely richer.
- **Rules in as next target**: the two-index (k,m)-style DP, which is the only
  object here with a closed recurrence form and is exactly what thread
  [[lift_gkm_to_3d]] needs.
