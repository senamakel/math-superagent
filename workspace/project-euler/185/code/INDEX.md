# Index — code

What each file in this folder is for. Keep it current: describe a file when you create it, and refresh this index after adding, renaming, or deleting files.

| File | Purpose |
| --- | --- |
| `AGENTS.md` | Working guidance for the code/ tree: package-tree conventions — one job per file, programs live here with their outputs in code/out/, shared imports in code/lib/, the naive program stays as oracle, exact arithmetic, no exponential time/space, never delete a program carrying a result. |
| `brute.py` | Naive brute-force oracle for PE185: enumerates all 10^L digit strings via itertools.product and returns those matching every (guess, c_i) exact-position-count constraint. Verified on the L=5 worked example: reports unique string 39542 among all 100000 candidates. Deliberately not run at L=16 (10^16 candidates). |
| `diag.py` | Diagnostic probe of the backtracking solver for PE 185: runs the L=5 instance to confirm the oracle (39542) and probes the L=16 instance's node count under a budget (500M), reporting solutions found and nodes visited. Used to judge whether the recursive solver is fast enough at full size before committing to it. |
| `diag16.py` | Diagnostic probe of the backtracking solver on the L=16 PE 185 instance only: measures the MCV-order search's node rate and progress under a 100M-node cap with a 120s timeout guard, reporting solutions found and nodes visited. Complements diag.py (which probes L=5 and L=16 together) and diagL5.py (L=5 only). Used to judge whether the recursive solver is fast enough at full size. |
| `diag16b.py` | Diagnostic instrumentation of the PE 185 L=16 backtracking search: records average branch width per depth and tries digit-ordering heuristics under a node cap (default 1M). Used (with diag.py, diag16.py) to judge whether the recursive MCV solver finishes at full size. Superseded by the final solution.py run. |
| `diag16c.py` | Diagnostic probe of the PE 185 backtracking solver: tests whether a strong forward-checking lower bound av[i] (number of unassigned positions whose feasible digit set still contains guess i's digit) beats the loose bound on L16, reporting nodes under a 50M-node cap. Complements diag16.py and diag16b.py in judging whether the recursive solver finishes at full size. Superseded by the final solution.py run, which solution2.py independently verified. |
| `diag16d.py` | Diagnostic probe of the PE 185 backtracking solver: strong forward-checking av[i] lower bound variant (same as diag16c.py) with periodic progress output and a lower 2M-node cap, to watch the L16 search rate and node growth during the run. Complements diag16.py, diag16b.py, diag16c.py in judging whether the recursive solver finishes at full size. Superseded by the final solution.py run, which solution2.py independently verified. |
| `diag16e.py` | Diagnostic probe of the PE 185 backtracking solver (variants measured during solver development; superseded by solution.py / solution2.py). |
| `diagL5.py` | Diagnostic probe confined to the L=5 PE 185 example: a standalone recursive backtracking solve (feasible-digit pruning) printing the solution and node count, giving the L=5 baseline. Head of the file has a half-written placeholder solver that is never run; only the bottom solve5() executes and is sound. Superseded for full runs by diag.py, which probes L=5 and L=16 together. |
| `pat_c1_l5.py` | Tests the c=1 distinct-position conjecture against the L=5 oracle 39542: the two single-hit guesses match at distinct positions {0,2}, both even. Gives the second instance supporting the weak c=1-distinctness conjecture. For the pattern finder. |
| `pat_extract.py` | Pattern finder's first-pass extractor of PE185 sequences from the constraint data (c_i counts, per-column digit sequences, row/column sums) for the exact sequence tools; established that the published constraint data has no exploitable integer-sequence structure. |
| `pat_minmult_c1.py` | _(undescribed)_ |
| `pat_structure.py` | Exact falsification-run for the pattern finder: tests two concrete structural hypotheses about the L=16 secret (H1 column-majority rule — falsified at 15 of 16 positions; H2 uniform match-position-pair design — falsified, 30/120 pairs covered), plus per-guess multiset overlap report. Negative results recorded in SCRATCHPAD.md and Cognee. |
| `pat_verify.py` | Pattern finder's own independent re-verification that the L=16 MILP answer 4640261571849533 satisfies all 22 (guess, c_i) exact-count constraints; reproduces the L=5 brute-force oracle (unique 39542) and reports the digit histogram. Output quoted in the final pattern report. |
| `solution.py` | Efficient recursive backtracking solver for PE 185 (constraint-satisfaction, most-constrained-variable heuristic with feasibility pruning). Reproduces L=5 oracle (39542) and reports the L=16 secret; the primary fast route. Cost scales with constraint structure, not 10^L. |
| `solution2.py` | Independent second route to PE185 via scipy.optimize.milp (branch-and-bound ILP). Builds binary vars x[p][d] (secret[p]==d), constraints sum_d x[p][d]==1 per position plus sum_p x[p][guess_i[p]]==c_i per guess, zero objective, all binary. L=5 reproduces 39542 (matches brute 100000-check and uniqueness by no-good cut); L=16 yields secret 4640261571849533 with all 22 counts verified and uniqueness confirmed (re-solve with a no-good cut infeasible). Runtime ~0.16 s for the solve. This is the independent verification of the backtracking solution.py. |
| `solution3.py` | Independent THIRD route to PE 185 via Google OR-tools CP-SAT (cp_model), distinct from the backtracking (solution.py) and scipy MILP (solution2.py). Integer vars digit[p] in 0..9, boolean match[i][p] <-> digit[p]==guess[i][p], sum_p match[i][p]==c_i. Reproduces L=5 = 39542 (matches brute oracle and uniqueness via no-good cut); L=16 = 4640261571849533 with all 22 counts verified and uniqueness confirmed (forbidding the string is infeasible). Runtime ~0.02 s. Cross-checks the independent solver solution2.py and gives a second independent route. |
