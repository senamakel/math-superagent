# Index — code

What each file in this folder is for. Keep it current: describe a file when you create it, and refresh this index after adding, renaming, or deleting files.

| File | Purpose |

| `AGENTS.md` | Folder convention doc for code/: every program lives here and its output in code/out/; how to describe programs in the index (say what establishes correctness: examples reproduced, brute agreement, size reached); one job per file, exact arithmetic, never delete a program carrying a result. |
| `arrangement_pn.py` | EXACT arrangement oracle for p(n,L) at n=3 and n=4, over integer L. Uses the fact that common scaling of the Exp(1) speeds preserves the race outcome, so p(n,L)=(n-1)!·(Euclidean measure of even-parity cells) on the unit speed simplex in free coordinates. Enumerates the cells of the linear arrangement of all candidate-event-time equalities (finish times F_j=(L-40j)/v_j, catch times C_ab=40(b-a)/(v_a-v_b), and v_a=v_b lines) by polygon clipping (2D, n=3) / polyhedron vertex+volume enumeration (3D, n=4), evaluates the exact race at each cell centroid via exact_race.outcome_parity_exact, and sums exact cell areas/volumes. Anchor checks p(3,160)=56/135 and p(4,400)=0.5107843137 built in; writes code/out/exact_pn.json. The exact (non-exhaustive-MC) solver, giving exact rationals the faster/nonexact methods are checked against for n=3,4. |
| `brute.py` | Naive exact oracle for PE 597: chronological race simulation + parity of the new order derived from bump chains. Exposes `simulate_order`, `parity_of_new_order`, `outcome_parity`. Reproduces all five rows of the n=3,L=160 table. Uses full-reachability `above` (the multi-bump edge-loss bug is fixed), so it is the reference-correct engine — byte-identical in dynamics to `simulate_order_nobug.py`. |
| `bump_forest.py` | TASK 2. Returns the bump forest as a parent array (`parent[j]=k` when boat j bumped k, None for finishers); each boat bumps at most once so `parent[]` is a valid parent array. Verifies over N=1e6 trials at n=3,L=160 that the forest ancestor-descendant-pair count mod 2 equals `brute.outcome_parity` — the parity == (# bumped chain pairs) correspondence. MC verifier, not a solver. |
| `bump_study.py` | Monte Carlo structural study (small n, L=160): for each sample records parity, bump multiset, finishes, chain-pair count; verifies `parity == (#chain pairs) mod 2` on every sample and histograms bump-pattern types split by parity. MC driver, not a solver. |
| `check_counterexample.py` | Sanity/oracle check: validates the counterexample pair ce1/ce2 (n=3) give opposite parities with float and exact agreement, and prints uniform-grid even-count ratios for M in (8,16,32). Grid converges to 0.5, not 56/135 — a sampling-measure artifact (uniform grid ≠ Exp(1)), not a parity bug. |
| `cross_decoupling_test.py` | Decisive test (Q1/Q2/Q3, N=200k default) of the research-library treap recursion for PE 597 against the true race oracle: Q1 asks whether cross (left/right index pairs joined by a bump chain) ALWAYS equals left-count times right-count; Q2 whether cross depends only on the min-W root identity (decoupling); Q3 whether parity(left)*parity(right)*(-1)^cross with TRUE cross reproduces the oracle (tautological). Diagnostic of the treap recursion hypothesis, not a solver. |
| `cross_direct_test.py` | Direct test of the two decisive treap claims at the root: (a) is cross == r*(n-1-r) always?, and (b) is cross constant across speed vectors sharing the same min-W root? Counts violations against the true race oracle across (n,L) configs. Diagnostic of the treap hypothesis, not a solver. |
| `crux_decoupling_test.py` | Crux decoupling test (N=300k default) of the treap hypothesis for PE 597: D1/D2 ask whether parity of the left/right sub-range in the final permutation equals the sub-race oracle parity on that slice; D3 whether true cross equals left-times-right; D4 whether recursion(true cross, true sub-race) reproduces full parity; plus per-root cross-value dispersion. Diagnostic of the treap recursion, not a solver. |
| `exact_race.py` | Exact-rational race dynamics mirroring the fixed `brute` on Fractions (`simulate_order_exact`, `outcome_parity_exact`); tuple-vs-Fraction comparison bug fixed so it runs. Uses full-reachability `above` like the fixed `brute`. |
| `examine_multibump.py` | Retired diagnostic that once demonstrated the multi-bump overwrite bug in `brute.simulate_order`: `bumped_by[k]` kept only the last bumper, silently losing earlier bump edges. The bug is since fixed in `brute.py`, so this now only shows the correct full-reachability behavior; kept as the record of the bug. Not a solver. |
| `high_precision_mc.py` | High-precision parallel Monte Carlo for p(n,L) using the verified `brute.py` engine. Each worker runs its own RNG seed and chunk; results pooled with binomial-mean SE. Usage: `python3 high_precision_mc.py n L total_samples` (one process per (n,L)). MC estimator, not exact. |
| `monte_carlo.py` | Plain Monte Carlo oracle: draws iid Exp(1) speeds and counts even-parity outcomes via `brute.outcome_parity`, printing an estimate of p(n,L). Fallback exact-tie-break note; plain N-event MC. |
| `p2_verify.py` | Verifies the derived exact closed form for n=2: p(2,L)=L/(2L−40). Boat0 bumps boat1 iff v0/v1 > L/(L−40), so P(bump)=(L−40)/(2L−40) and p(2,L)=1−P(bump)=L/(2L−40). Checks the closed form against the brute oracle by high-N Exp(1) MC at L in (48..40000). Validation check for the exact method, not a solver. |
| `p3_mcverify.py` | Independent cross-engine MC check of the exact p(3,L) values in code/out/exact_pn.json (from arrangement_pn.py): estimates each exact value with N Exp(1) trials via the brute.py outcome_parity oracle and prints exact-vs-MC difference with SE. Second route confirming the arrangement solver's p(3,L). |
| `p_cell_exact.py` | _(undescribed)_ |
| `parity_recursion.py` | Implements the claimed range-parity recursion borrowed from CONTEXT.md/research (root = argmin of W_i = v_i/(L-40i) over the index range, parity = left*right*(-1)^cross) and tests it against the brute oracle outcome_parity on random Exp(1) speed vectors. Records each concrete mismatch. Diagnostic of the recursion hypothesis, not a solver. NOTE: needs `simulate_order` from brute.py to compute `above` reachability for cross. |
| `pn_exact.py` | Sketch/intent file for exact p(n,L) at small n by subdividing the speed simplex with candidate-event-time separating lines (v_a=v_b and equality of finish/catch times), measuring each cell's exact area and reading the race outcome at an interior rational point. Currently the cell-enumeration is DEFERRED (main() only prints a deferral note); kept as the plan/record, not a working solver. |
| `run_crux.py` | Driver that runs the two treap-decoupling diagnostics (cross_direct_test.py and crux_decoupling_test.py) via subprocess with fixed N and prints their output. Convenience runner, not a solver; produces no new result itself. |
| `scratch_verify_invexp.py` | RETIRED / superseded. One-off retired MC scratch verifying an inverse-exponential claim; the claim is now sourced in `research/inverse_exponential_finish_times_wikipedia.md`. Kept as a record only. |
| `simulate_order_nobug.py` | Corrected race engine fixing the multi-bump overwrite: records every bump edge and computes placed-below sets by graph reachability. Same API as `brute.simulate_order`. Now duplicate of the fixed `brute.py` (the correction was merged into `brute`); kept as the record of the fix. |
| `structure_taxonomy.py` | TASK: reproduces the n=3,L=160 five-row worked table with the brute engine (parities + exact rational row-prob sums 1 and 56/135), MC-verifies p(4,400)~0.5108, and MC-taxonomizes the bump directed graph over (n,L): shows every bump graph is a directed forest (out-degree<=1, strictly index-increasing edges, no cycles), charts degree/chains/edge-set statistics, and notes forest components act on disjoint index intervals. See structure_report.md for the write-up. |
