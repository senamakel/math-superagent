# A083652 — summatory binary length

**Source:** https://oeis.org/A083652 (full text at `L0/a083652.full.md`)

**What it is:** `A083652(n)` = sum over k=0..n of the binary length of k
(number of bits in the binary expansion). Values 1,2,4,6,9,12,...

**Closed form (exact, O(1)):**
`a(n) = (n+1)·bit_length(n+1) − 2^bit_length(n+1) + 2`
= via the generating function `1/(1-x) + (1/(1-x)^2)·Σ_{j≥0} x^{2^j}`.
(Fischer; Luschny's PARI/Python give the same one-liner; A296349 is an
essentially identical sequence.)

**Why it matters here:** binary length = #1-bits + #0-bits, so
`total_bits(n) = A000788(n) + A059015(n)`. This is the third leg of the
identity ``[[zerocount]]`` already records (A059015 = A083652 − A000788), the
source of `B(n)` in the (A,B) counting game. Because `a(n)` is a closed form
(not a recurrence), it is the cleanest way to obtain the *unweighted* total-bit
count; the run's weighted `B(n)=Σk·zerocount(k)` still needs per-bit weighting
(see [[counting-arithmetic]]).

0-bits), A070939 (length of a single n), A000788 (summatory 1-bits).
